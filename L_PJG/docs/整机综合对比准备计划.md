## 1. 两版定义（BEFORE / AFTER）

| 项 | BEFORE（compact 基线） | AFTER（fused 目标） |
|---|---|---|
| 源码快照 | git HEAD（提交 `62c05c0` / `80a9c7d` 之后，PE 均为 compact 逐级截位版） | 当前工作树（3 个 PE + filelist 的未提交修改） |
| G_PE / G_PE_diag / MF_PE | compact：`complex_multiplier` + `complex_adder` 累加树，每级按 `qtz_def.svh` 截位 | fused：单个 `complex_mac_w_bias`（全位宽乘积 + 全宽累加 + **输出端单次截位**），`MUL_IN_PAIR_NUM=SYSTOLIC_PARALLEL`、`FAST_MODE_EN=0`（Gauss 3 乘，与 compact 同算法） |
| LPJG_unit 用的 `complex_multiplier` | compact 单元（`rtl/arithmetic_unit/complex_multiplier.sv`） | full 单元（full-lib `complex_multiplier.sv`，单次截位） |
| 其余算术单元 | `complex_adder` / `complex_addsub` / `complex_real_multiplier` / `real_multiplier` / `real_adder` / `real_addsub` / `complex_conj` / `complex_negative` / `real_negative` / `reciprocal_lut.v` | **已统一改为从 `arithmetic_unit_full/` 解析**（2026-09-06 本会话后段）。这些单元两库**逐字节相同**（本地行级 diff + EDA md5 双重验证），故"换库"是文件级零语义改动、bit-safe；整机 FC 复验 0/32（`vcs_top_fc_16_optb_full`）。对整机综合 BEFORE/AFTER **无新增面积贡献**（内容差异仍只在 `complex_multiplier` 与 fused MAC） |
| 阵列规模 | TX=32, SYSTOLIC_PARALLEL=2, VEC_MUL_NUM=8, RX=128 | 相同（位宽/量化完全不动） |

> **与量化位宽的关系**：BEFORE/AFTER 的所有 `qtz_t`（H/Y/G/G_MAC/GD/YMF/X/A_DIAG_INV/N0）参数完全一致，仅 MAC/乘法的**截位时机与次数**不同（compact 逐级截位 vs full MAC 内部全宽 + 输出端截位）。因此功能差异只能由位宽/截位引入；当前 policy 要求整机 FC **0-LSB 位精确**通过后才允许综合（见 §6）。
>
> **⚠️ 根因记录（本阶段，2025 调查）**：r4 FC 对三个 fused golden（fullsum 11/32、leaf 12/32、gauss 13/32 精确，其余均恰差 ±1 LSB）全失败。根因：fused `complex_mac_w_bias` 虽然内部全宽、只在输出端一次截位，但其**反馈寄存器是有宽截位的** —— `G_reg` = `G_MAC_QTZ`(1,9,10) fp10、`y_mf` = `YMF_ACC_QTZ`(1,10,8) fp8。systolic 每拍（SYSTOLIC_PARALLEL=2 根天线，INPUT_CC=64 拍/迭代）累加 2 个全宽乘积后**寄存器每拍都被 floor 到 fp10/fp8**，即每个元素每迭代 64 次逐拍截位；而三个 golden 都把 sites 1&2 建模成「128 天线整段求和后单次截位」，结构不符。compact 之所以 0/32 匹配，是因为它把每个乘积先 floor 到 fp10 再精确加法树累加，逐乘积 floor 与分组无关，平台无需调度保真。fused 的 `floor_fp10(reg+p1+p2)` 与 compact 相差 carry∈{0,1} fp10-LSB，且**依赖逐拍天线配对顺序**（systolic H_send/H_conj_send 延迟网络）。
>
> 由此有两条路：
> - **Option A（推荐，不改硬件）**：让 MIMO 平台按 RTL 真实调度建模「逐拍寄存器截位」（镜像调度/配对 → 重生成 golden → FC 应 0/32）。**若 FC 0/32 通过，功能语义即锁定为「每拍截位」**，综合面积对比需如实说明 AFTER 的寄存器位宽不变、只是把 compact 的逐级截位换成每拍截位+内部全宽，面积下降来自消除中间截位级。
> - **Option B（后续 RTL 升级，需用户批准，先不综合）**：把 `G_reg`/`y_mf` 反馈寄存器加宽到 `complex_mac_w_bias` 内部全宽（fp12+），使每迭代仅 1 次真正的全宽单次截位（与 golden 的单次截位语义天然一致、功能更接近理想）。这会改变寄存器位宽/面积，是**下一轮**的硬件改动，**不在本轮综合对比范围**。
>
> **✅ Option B 已实施并验证（本会话）**：
> - 用户批准 Option B：允许把专门累加寄存器位宽扩到对应全宽；MIMO 平台矩阵乘法中间量化已用 `full_mac`（单次截位）——即 **gauss golden（[x_p8_fused_rtl_gauss.txt](../fc_golden/x_p8_fused_rtl_gauss.txt)，md5 `29cdbe71`）本身就是 Option B 语义的 golden**，无需重新生成。
> - RTL 改动（**只动 4 个文件，`complex_mac.sv` 未动**——其内部 ACC3 已够宽）：
>   - [params.svh](../rtl/vinc/params.svh)：新增 `G_ACC_FULL_QTZ = get_qtz(1,10,12,COMPLEX)`（fp12=H.fp+H.fp，int10=MAC ACC3 全宽）与 `YMF_ACC_FULL_QTZ = get_qtz(1,13,11,COMPLEX)`（fp11=H.fp+Y.fp，int13=ACC3 全宽）；旧 `G_MAC_QTZ`/`YMF_ACC_QTZ` 保留（`g_pe_area_compare` 实验 bench 仍引用）。
>   - [G_PE.sv](../rtl/G_systolic_array/G_PE.sv) / [G_PE_diag.sv](../rtl/G_systolic_array/G_PE_diag.sv) / [MF_PE.sv](../rtl/G_systolic_array/MF_PE.sv)：`G_reg`/`y_mf`/`mac_out`/MAC `INPUT_C_QTZ`/`OUTPUT_QTZ` 从 fp10/fp8 加宽到上述全宽 → 每拍回馈为恒等 transfer，整段扫描**只在新旧两处做单次截位**（G 存到 `G_QTZ` fp5、y_mf 存到 `YMF_QTZ` fp8）。PE 端口位宽（`G_QTZ`/`H_QTZ`/`YMF_QTZ`）不变 → 父级 `A_systolic_array.sv` 与 testbench 不受影响。

## 4. 综合方法与约束（决策点，先列不执行）

PE 级对比（`g_pe_area_compare`）用的方法学：**logic 模式、单 TT 角、no retime / no -spg**，保证逐实例面积跟随 RTL 结构、前后可比；约束 800 MHz + 20% setup uncertainty，TSMC 28nm TT（`tcbn28hpcplusbwp30p140`），DC J-2014.09-SP3。

整机对比可选的流程：
- **方案 A（推荐，先做结构面积）**：整机 logic 模式 `compile_ultra -no_autoungroup`（或普通 `compile`）但**关 retime / 关自动 ungrou**，把 PE 级方法学平移到整机，得到可逐层对比的 BEFORE/AFTER 面积/功耗。
- **方案 B（工程时序）**：走仓库已有的 topo 流程 [script/syn.tcl](../script/syn.tcl)（`create_scenario` SSG/FFG/TT + `compile_ultra -spg -retime` + 时钟门控），得到整机时序/面积/功耗报告，但 retime/ungroup 会模糊「纯算术替换」的面积归因，需要额外 `-hierarchy` 分析。

两类结果可以都出（B 作为工程基线、A 作为归因），但**首轮对比建议只跑 A**，与 PE 级报告口径一致。

整机特有的核查项（决定可综合性与结果可信度）：
1. **RAM 映射**：`SP_Ram.v` / `SP_Ram_array.sv` 在 DC 下如何映射（行为级 RAM → compile 成寄存器堆，或需要 RAM 模型/`compile_ultra -retime` 是否动 RAM）。要保证 BEFORE/AFTER 采用**相同**的 RAM 处理，否则 RAM 面积差异会污染对比。
2. **时钟/复位/端口约束**：顶层 `detector` 只有 clk/rst_n + 端口向量；约束参考 [script/a_timing.con](../script/a_timing.con)，时钟周期 1.25 ns + 20% uncertainty，与 PE 级一致；`n0_in`、`iter_num_i`、`finish_flag_i` 等控制端口按功能驱动或设 `case_analysis`，保证输入不悬空。
3. **寄存器数量对比**：PE 级对比中三版寄存器均为 187；整机应单独报 `report_area -hierarchy` + `report_power -hierarchy`，确认 BEFORE/AFTER 仅算术逻辑变化、寄存器基本不变（fused 消除中间级截位寄存器可能略减——这本身是要观察的结论之一）。
4. **VCS2014 兼容**：整机 RTL + full-lib 已通过 `sim_rtl_fc.f` 的 VCS2014 编译（r4 各阶段），DC analyze 用同一份文件列表即可；full-lib 的 hoist 修改是语义保持的，不影响面积。
